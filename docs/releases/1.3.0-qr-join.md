# Rilis 1.3.0 — QR Join Dompet (statik + approval)

Status: **implementasi lokal selesai dan terverifikasi; rilis produksi belum dijalankan.**

Tanggal dokumen: 2026-10-19. Versi aplikasi **1.3.0**, Android `versionCode` **4**, channel publik tetap `preview`, channel kandidat `qr-join-qa`.

## Ringkasan perubahan

Undangan dompet kini punya dua bentuk:

- **Undangan sementara** (perilaku lama): token baru, kedaluwarsa 7 hari, dibuat server untuk member terdaftar.
- **QR statis**: satu QR reusable per dompet. URL invitation sama sampai admin melakukan reset atau menonaktifkan. QR berisi URL HTTPS biasa, sehingga kamera HP / Google Lens dapat membukanya, sementara scanner bawaan aplikasi membuka alur undangan langsung tanpa browser.

Perubahan inti: **scan bukan keanggotaan**. Pemohon mengirim permintaan; pemilik atau admin menyetujui/menolak. Sebelum approval tidak ada baris `workspace_members` dan tidak ada akses data keuangan.

## Bagian backend (migrasi, belum diterapkan ke produksi)

| File | Isi |
| --- | --- |
| `supabase/migrations/20261019000100_qr_join_schema.sql` | `kind` invitation, `revoked_at`, batas lifecycle, satu static aktif per dompet, tabel `workspace_join_requests`, flag `qr_join_enabled` |
| `supabase/migrations/20261019000200_qr_join_rpc.sql` | Sembilan RPC entry point + helper privat (owner/admin, identitas terdaftar, gate fitur) |
| `supabase/migrations/20261019000300_qr_join_cutover.sql` | Pemotongan RLS: hapus kebijakan direct-enroll, bootstrap owner, helper legacy terikat `auth.uid()` |

Poin keamanan yang sudah dibuktikan pada PostgreSQL disposable:

- Jalur lama yang membolehkan `authenticated` menulis `workspace_members` langsung **ditutup**; ada *positive control* yang sengaja mereproduksi kebocoran pada baseline lalu membuktikan penutupannya.
- Sembilan RPC: `preview_workspace_invite`, `create_workspace_invite`, `manage_workspace_qr`, `get_workspace_join_state`, `submit_workspace_join_request`, `list_my_workspace_join_requests`, `list_workspace_join_requests`, `decide_workspace_join_request`, `cancel_workspace_join_request`.
- Race dua sesi PostgreSQL independen (submit ganda, approve-vs-reject, approve-vs-reset) aman berkat advisory lock + guard status + unique constraint.
- Order retry memakai `clock_timestamp()` agar tidak tertukar dengan timestamp transaksi.
- Helper legacy `user_workspace_ids` / `user_admin_workspace_ids` kini terikat `auth.uid()`, menutup enumerasi UID orang lain.
- `manage_workspace_qr('get')` kini **read-only**: dompet tanpa QR aktif melaporkan `disabled` dan admin menekan `enable` untuk membuat QR. `enable`/`reset` adalah satu-satunya jalan membuat QR baru.
- `decide_workspace_join_request` memeriksa `qr_join_enabled()` khusus untuk keputusan `approved`. Jadi kill switch menghentikan **admission**, tetapi `rejected` tetap berjalan untuk membersihkan antrean. `list_*` dan `cancel` sengaja tidak dipegang flag agar status/cancel tetap berfungsi saat fitur dimatikan.
- Grant `select` anon pada `workspace_members` dicabut. Kebijakan `wm_select`/`wm_delete`/`invite_select` tidak punya klausa role, jadi tanpa pencabutan itu anon akan gagal di tengah evaluasi kebijakan; dengan pencabutan, penolakan terjadi di pemeriksaan privilege seperti dua tabel lainnya.
- `create_workspace_invite` dapat dipanggil member biasa untuk undangan sementara (maksimal 7 hari) — kemampuan yang sudah ada, dicatat di sini agar tidak dianggap kebocoran.

## Bagian aplikasi

- `lib/inviteLinks.ts` — parser/builder kanonik dengan allowlist host (`dompet-bareng.vercel.app`, `dompetbareng.app`) dan skema `dompetbareng://invite/<token>`; menolak kredensial, port, dan normalisasi path mentah.
- `lib/pendingInvite.ts` — intent login bertahan maksimal 24 jam, tervalidasi, dibersihkan saat cancel/logout/sukses.
- `context/WorkspaceContext.tsx` — aktivasi dompet memuat ulang keanggotaan aktual dari server; hasil setelah ganti akun/blur dibuang; `joinWorkspace()` tidak lagi menulis keanggotaan langsung.
- `hooks/useInviteAdmission.ts`, `useJoinRequests.ts`, `useWorkspaceQr.ts`, `useInviteNavigation.ts` — polling + realtime sebagai petunjuk, guard scope akun, timeout RPC 15 detik dengan AbortController, `feature_disabled` bila RPC belum ada.
- `components/WorkspaceQrPanel.tsx` — QR asli (`react-native-qrcode-svg`, quiet zone 32, latar putih), reset/disable dengan konfirmasi, disabled tidak otomatis aktif lagi.
- `components/WorkspaceJoinRequestsPanel.tsx` — antrean approve/reject admin dengan hitungan pending.
- `components/InviteQrScanner.native.tsx` — `CameraView` QR-only, satu hasil per sesi (guard frame ganda dan frame tertunda setelah background), melepas kamera saat blur, input manual selalu tersedia; `.web` fallback manual.
- `app/scan-invite.tsx`, `app/join-requests.tsx`, `app/invite/[token].tsx` — layar scan, My Requests, dan landing undangan berbasis approval.
- Salinan ID/EN baru di `lib/inviteTranslations.ts`; note share sementara kini menyebut persetujuan pemilik/admin.

## Rantai runtime kamera

- `expo-camera` **57.0.6** dipasang dengan config plugin: `cameraPermission` teks lokal, `microphonePermission: false`, `recordAudioAndroid: false`, `barcodeScannerEnabled: true`. Aplikasi tidak meminta akses mikrofon.
- Kamera butuh **APK/runtime baru**; perubahan ini tidak dapat dikirim lewat OTA ke runtime 1.2.0.

## Gerbang publikasi APK (pengaman rilis)

`api/eas-webhook.js` tidak lagi mempromosikan setiap build selesai. Perubahan:

- Verifikasi signature `expo-signature` (HMAC-SHA1 atas **byte asli** request) dengan `timingSafeEqual`; body tanpa byte asli ditolak.
- Seleksi gagal tertutup: build harus **finished + android + preview + internal + versi/code persis dari `app.json` + build ID dan URL persis yang disetujui operator**. Profile `qr-join-qa` tidak pernah promotable. URL harus `https://expo.dev/artifacts/eas/<nama>.apk`.
- Variabel konfigurasi (nama saja, nilai tidak pernah ditaruh di repo): `EAS_WEBHOOK_SIGNING_SECRET`, `APK_PROMOTION_HOLD`, `APK_PROMOTION_BUILD_ID`, `APK_PROMOTION_BUILD_URL`, `WEBHOOK_APK_SECRET`.
- Tidak ada lagi fallback rahasia hardcoded; `config.api.bodyParser = false` agar byte asli tersedia.
- `scripts/sync-latest-apk.js` wajib `--build-id <id>`, memakai selektor yang sama, dan mendukung `--dry-run`.

Sebelum konfigurasi ini diaktifkan di Vercel, webhook lama **masih menulis APK apa pun yang selesai**. Jadi: deploy webhook baru dengan hold menyala **sebelum** memulai build 1.3.0.

## Audit dependensi (`npm audit`)

35 temuan: **1 critical, 23 high, 11 moderate**. Tidak ada upgrade senyap; semuanya transitive dari toolchain Expo/React Native dan tidak ada yang diperbaiki dengan mengorbankan kompatibilitas SDK 57.

| `react-native` / `metro` / `micromatch` / `braces` | high | Toolchain build |

Tindak lanjut terpisah: perbarui saat Expo SDK merilis rantai yang sudah diperbaiki, jangan pin manual di luar versi yang didukung SDK.

## Urutan cutover produksi (memerlukan otorisasi terpisah)

1. Deploy **web + webhook baru** dengan `APK_PROMOTION_HOLD=true` dan secret signing terisi.
2. Terapkan migrasi `000100` → `000200` (gate `qr_join_enabled` tetap false).
3. Build kandidat `qr-join-qa`, verifikasi isinya, uji di perangkat.
4. Terapkan migrasi `000300`; baca ulang definisi policy/grant, pastikan tidak ada policy permissive kedua pada `workspace_members`.
5. Set `APK_PROMOTION_BUILD_ID` / `APK_PROMOTION_BUILD_URL` untuk build final, lepas hold, sinkronkan build itu saja.
6. Smoke dua akun di dompet QA.
7. `qr_join_enabled=true`, baca ulang nilainya.

## Rollback / forward-fix

- Masalah kritis saat cutover: set `qr_join_enabled=false` (berhenti menerima undangan baru, status/cancel request tetap jalan), nyalakan lagi hold promosi, lalu forward-fix.
- Jangan pernah membuka kembali INSERT `workspace_members` langsung.
- Perbaikan JS kompatibel cukup lewat OTA ke runtime 1.3.0; perbaikan native butuh `versionCode` lebih tinggi.
- APK publik tetap menunjuk 1.2.0 sampai seluruh gate di atas selesai.

## Kompatibilitas

Ada batas kompatibilitas eksplisit: APK lama tidak lagi bisa menghasilkan undangan atau bergabung lewat tulisan langsung, karena kebijakan lama sudah ditutup. Penggantinya adalah APK baru dan alur browser. Bypass tidak dipertahankan demi kompatibilitas.
